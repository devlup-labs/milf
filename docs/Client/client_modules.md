# Client Side Core Modules

The Client application is structured modularly using React, Vite, and standard best practices. Here is a breakdown of the core modules and how they interact:

## 1. Routing & View Layer (`src/pages`)
These form the primary views of the application, wired together by `react-router-dom`:
- **Authentication**: `Login.tsx`, `Signup.tsx` - Handles user onboarding and access.
- **Dashboard (`Dashboard.tsx`)**: The main overview summarizing function statuses, recent invocations, and stats.
- **Functions Management**:
  - `Functions.tsx`: Lists all available lambda functions.
  - `CreateFunction.tsx`: The form interface to define a new lambda (runtime, memory, schedule, source code).
  - `FunctionDetail.tsx`: Detailed view for a specific function, including execution history and configuration.
- **Observability**:
  - `Logs.tsx`: A centralized view for searching and filtering execution logs across functions.
  - `Invocations.tsx`: History of all function executions, showing success/failure states and durations.
- **Resources**:
  - `Files.tsx`: A file explorer interface likely meant for managing shared volumes or persistent storage for lambdas.
- **Administration**:
  - `Settings.tsx`: User preferences and account management.
  - `Billing.tsx`: Resource usage tracking and cost estimations.

## 2. API & Data Fetching Module (`src/lib/api.ts` & `src/hooks/useQueries.ts`)
This is the nervous system of the client, responsible for communicating with the backend Server:
- **`lib/api.ts`**: Contains the raw asynchronous `fetch` functions interfacing with the Go backend's REST endpoints (`/api/v1/lambdas`, `/api/v1/invocations`, etc.).
- **`hooks/useQueries.ts`**: Wraps the raw API calls using `@tanstack/react-query`. This module manages caching, background refetching, and synchronous state mapping for the UI components.

## 3. Authentication Context (`src/contexts/AuthContext.tsx`)
A global React Context provider that wraps the entire application:
- Manages the active `Session` object.
- Handles standard login mutations alongside Google OAuth integration (`@react-oauth/google`).
- Orchestrates token persistence (currently `localStorage`) and token injection into API requests.

## 4. Component Library (`src/components`)
A reusable system of UI elements ensuring a consistent look and feel:
- **Layout Module (`/layout`)**: Contains `AppLayout.tsx`, `TopNavbar.tsx`, and `LeftSidebar.tsx` which frame the authenticated area of the app.
- **Shared Domain Components (`/shared`)**: Higher-level, reusable components specific to this app's domain, such as `FileExplorer.tsx` (the UI for the Files page), `DataTable.tsx` (used in Logs/Invocations), and `StatsCard.tsx`.
- **Base UI Elements (`/ui`)**: Low-level, generic components generated by Shadcn UI (buttons, dialogs, inputs, toasts).
- **Specialized Components**: `InvokeModal.tsx` which provides a dedicated UI for testing/invoking a function with custom JSON payloads.

## 5. Utilities (`src/lib`)
- **`inferParams.ts`**: Likely an AST parser or regex utility designed to infer expected parameters from source code to aid developers in the UI.
- **`utils.ts`**: General helper functions, such as Tailwind class merging (`cn`).

## Interaction Flow
1. The **Routing Layer** determines which Page to display.
2. The Page checks the **Auth Context** for permissions.
3. The Page calls hooks from **`useQueries.ts`**, which trigger requests via **`api.ts`**.
4. Data is cached and passed down to **Shared Components** for rendering.
